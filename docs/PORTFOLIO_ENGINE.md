# 组合账户与订单引擎（阶段三）

更新：2026-10-27。状态结构版本：1。

本说明记录阶段三引擎；阶段四已接入用户归属、HTTP 路由、恢复、迁移和结束报告，见 [PORTFOLIO_API.md](PORTFOLIO_API.md)。可操作的组合页面属于阶段五。真实股票区间仍须有完整的历史状态和公司行为证明，仓库没有默认开放任何真实区间。

## 模块与边界

| 模块 | 职责 |
| --- | --- |
| `backend/portfolio_engine.py` | 一个共享现金账户、下单、撤单、推进、公司行为、FIFO 成本和账本核对 |
| `backend/portfolio_models.py` | 账户、持仓批次、订单、成交、流水、每日资产及序列化 |
| `backend/portfolio_rules.py` | 日期版本费率、交易单位、报价单位、涨跌停和资金估算规则 |
| `backend/portfolio_ledger_store.py` | SQLite 聚合状态和推进结果的一次事务提交、版本检查及失败回滚 |
| `backend/portfolio_replay.py` | 固定行情版本、公共日历、只读历史和引擎独立游标 |

没有调用或修改原单股交易模拟器。每个组合只有一个现金余额，股票只对应持仓批次。引擎复制回放游标并共享不可变的行情数据；外部原回放推进不会改变引擎日期。公开 `snapshot/history/switch_stock` 不提供未来行情，`history` 保留日期与复权检查。带 `_engine_` 前缀的方法仅供受信任的后端引擎使用，不得注册成路由或直接序列化内部对象。

## 调用方式

真实数据的 `calendar/quotes/securities/actions` 按 [数据说明](DATA_REPLAY.md) 准备。只有通过公司行为账本能力检查时才能用 `accounting=True` 创建有事件的回放。

```python
from uuid import uuid4
from backend.portfolio_replay import PortfolioReplay
from backend.portfolio_engine import PortfolioEngine
from backend.portfolio_ledger_store import PortfolioLedgerStore

replay = PortfolioReplay(stocks, start, end, calendar, quotes, securities, actions,
                         accounting=True)
store = PortfolioLedgerStore(independent_database_path)
engine = PortfolioEngine(replay, "100000", store=store)
order = engine.submit("600000", "buy", 100, request_id=str(uuid4()))
before = engine.snapshot()
operation_id = str(uuid4())  # 首次请求前生成；重试沿用此标识和原 expected_date
after = engine.advance(operation_id=operation_id, expected_date=before["current_date"])
engine.reconcile()
store.close()  # 外部传入的 store 由调用方关闭
```

未传 `store` 时使用内存 SQLite，调用 `engine.close()` 释放。传入文件路径时父目录须已存在，所有状态写在该独立文件中；不会读取原用户数据库。`advance` 未传操作标识时自动生成 UUID，响应返回 `operation_id`。网络调用方应在发送前生成标识，确保超时重试可用同一标识查询结果。

`submit` 返回订单；`cancel(order_id)` 返回撤销后的订单；`advance` 返回推进结果；`snapshot` 返回当前全部账户状态。格式、方向、代码、预算小数位等非法参数抛出 `ReplayDataError`；数量单位、现金/股数不足、非交易状态等业务拒绝形成 `rejected` 订单并保存中文原因。已到末日不能提交下一开盘订单。

## 金额与成本

- 所有价格、费用、现金和成本用 `Decimal`。报价单位 0.01 元；金额和每项费用分别按 `ROUND_HALF_UP` 四舍五入到分，JSON 输出十进制字符串。
- 买入批次成本为成交金额加买入全部费用。卖出按 FIFO 分配成本；部分批次成本按比例舍入，最终卖完该批次时结转全部剩余分位，避免尾差。
- 卖出已实现盈亏 = 卖出金额 − 卖出费用 − 结转成本；未实现盈亏 = 收盘市值 − 剩余成本。已核验的税后现金分红作为已实现收入，不重复冲减总成本。
- 每日资产包括现金、市值、总资产、当日资产变化额、累计已实现与未实现盈亏，以及各股估值日期和状态。初始日当日收益为零。
- `ledger` 同时记录开账、下单/撤单/拒绝、买卖、登记日权益和公司行为；现金流水是其中 `cash_delta` 非零的条目。成交保留价格、费用版本、市场规则版本、行情来源、行情版本及日线简化模拟说明。

## 订单与 T+1

当前日期表示已看到收盘信息，订单只在下一公共交易日开盘尝试一次，失败即拒绝并释放占用，不自动延后。顺序为订单提交顺序，不将卖单提前以资助较早的买单。

默认买单用当前收盘价加 10% 的估算缓冲及下一日费用冻结资金，缓冲可通过 `MarketRules` 配置。也可用 `budget="金额"` 指定包含全部费用的最大花费。冻结不扣减实际现金；多个买单共享可用现金。下一个开盘含费用超过该单冻结预算时，即使账户另有现金也拒单。提交和成交均不使用未知开盘价预先扩大额度。

买入单位默认 100 股，单笔最多 100 万股。卖单冻结股数，其他卖单不能重复占用。不足一手的部分须一次卖完，可以和整手合并，也可以单独整笔卖掉零股，不能拆分零股。

T+1 按实际买入日期校验，而非下单日期。`sellable_now` 不包含当天买入股数；`orderable_next_open` 包含到下一开盘已满足 T+1 与到账条件的股数。因此今天收盘可以买入后提交明天开盘卖出的订单，这不构成当天卖出。送转股另用核验过的 `available_on` 控制可卖日。

同一 `request_id` 与同一参数重复提交返回原订单，参数不同明确报错。撤单重复执行不重复释放；已成交、已拒绝的订单不可撤销。

## 日期版本费率和成交限制

默认规则只覆盖 **2022-04-29 至 2026-10-27**，训练区间在创建时检查完整覆盖。更早或更晚日期必须先补充有依据的 `FeePeriod`，不能套用当前规则。

| 成交日期 | 卖方印花税 | 双向过户费 | 版本 |
| --- | --- | --- | --- |
| 2022-04-29 至 2023-08-27 | 0.001 | 0.00001 | `cn-a-20220429-v1` |
| 2023-08-28 至 2026-10-27 | 0.0005 | 0.00001 | `cn-a-20230828-v1` |

佣金默认双向 0.0003，最低 5 元，是可配置的训练假设，包含交易经手费和监管费，不再重复计收这两项。过户费单列。构造 `FeeSchedule` 时可为不同日期配置佣金、最低佣金、税费和版本；引擎固定一份配置副本，外部对象之后的修改不影响本次训练。成交使用成交日规则，订单与成交均记版本。

普通主板按前有效收盘/经核验的除权参考价计算 10% 涨跌幅价格，价格舍入到分。超出支持范围的日线拒绝成交。注册制新股上市后前五个公共交易日不套用 10% 限制；日历不能确认近期上市交易日数量时拒绝成交。旧制上市首日额外定价规则尚不支持。

停牌、零成交量、尚未上市、已退市、无有效行情不能成交。一字涨停买入、一字跌停卖出保守拒绝；无涨跌幅限制日的一字行情也保守拒绝。其他成交明确标为日线简化模拟，不能重建真实开盘盘口、排队及流动性。

历史费率依据（核对于 2026-10-27）：

- [国金证券向投资者发布的中国结算过户费调整通知](https://download.gjzq.com.cn/gonggao/nr/CSDC_About_Transfer_Fee_Decrease_Tips.html)：2022-04-29 起沪深 A 股双向按 0.01‰ 收取。
- [上交所印花税减半通知](https://www.sse.com.cn/aboutus/mediacenter/hotandd/c/c_20230827_5725662.shtml)、[政府税收政策指引](https://www.hh.gov.cn/info/11441/683342.htm)：2023-08-28 起卖方单边 0.5‰。
- [上交所零股申报通知](https://www.sse.com.cn/lawandrules/guide/stock/jyglywznylc/tz/c/c_20230209_5716007.shtml)、[深交所主板注册制交易机制说明](https://investor.szse.cn/institute/rules/t20230727_602238.html)。

## 公司行为支持条件

完整性证明仍为前提，不把无事件记录当作无事件。默认数据回放保持阻断；`accounting=True` 仅启用已实现类型的结构检查，真实数据只能由受信任的后端导入者提供。

支持 `cash_dividend`（税后现金分红）与 `bonus_shares`（送股/转增），必须含事件编号、依据、区间内登记日、晚于登记日的生效日和明确的除权参考价。现金生效与入账、送转生效与股份计入需在同日（`window_end == effective_on`）；股份的可卖日可以更晚。登记日和生效日须为公共交易日。

登记日收盘在当天订单成交之后固定持股权益。之后卖掉股票仍保留登记日权益；登记日后买入不获得该次权益。分红按已核验的税后每股金额计入共享现金与已实现收益，不推算依赖未来持有期的红利补税。

送转使用登记日总股数计算股数，出现不足一股的权益时整次推进拒绝并回滚，不能擅自取整。存续登记日批次按送转比例将部分成本转到送转批次，总成本不变、每股成本摊薄；登记日后买入的批次不参与该次摊薄。登记日后已卖出部分保持先前已结转成本，该部分后续送转权益的剩余成本为零，不追改历史已实现收益。账本记入每个批次的股数及成本变更，可重建核对。

公司行为生效先于撮合，该股票未成交订单一律自动撤销并释放占用，提示重新下单；不会悄悄改订单股数或资金预算。停牌恰逢除权时以核验参考价估值并标记 `action_reference`、日期和 `stale`，后续停牌日沿用该标记，绝不把它用于成交。

配股、未知类型、拆并股、缺登记日、缺参考价、生效与入账分离、无法确定税后现金、权益尾数分配及从登记日之后才开始的事件区间仍明确阻止。当前验收均为合成事件；没有据此声称已完成真实股票公司行为全历史核验。

## 原子推进与账本校验

推进固定依次完成：检查下一公共日期与全部行情 → 公司行为与状态变化 → 按提交顺序撮合 → 收盘估值 → 汇总资产和当日收益 → 一次 SQLite 事务提交全部聚合状态及本次操作结果。只有提交成功后，才发布内存账户及回放游标；中途任何异常保持原状态。

`operation_id` 按训练唯一，重复请求返回原结果；同一标识用于另一日期报错。`expected_date` 是必填前置条件，不同标识的两个重复点击也不能连续推进两天。进程内锁覆盖所有账户写操作；SQLite 事务与版本比较防止过期状态覆盖。

`engine_state` 的 JSON 聚合同时包含当前日期、账户、批次、订单、成交、流水、权益、每日资产和版本。`engine_operation` 保存操作标识及原返回值，两者在一次事务中提交。阶段四的仓储将配置、固定行情和 HTTP 请求结果纳入同一事务，并使用 `PortfolioEngine.restore()` 恢复对象；不重新执行历史成交或开账。`end()` 撤销待成交订单并固定结束状态，`report()` 只允许在结束后提供完整区间复盘行情。

每次提交前从流水重算现金、持股、总成本、逐批次成本和已实现盈亏，并逐日核对“现金 + 持股 × 当日标记价格 = 总资产”以及“总资产 − 初始资金 = 已实现 + 未实现”。现金、数量和冻结额度不得出现负值或超额。调用 `reconcile()` 可取得重建结果。
